# Academy 多格式文档阅读器设计

日期：2026-07-17
状态：已批准，待实施计划

## 1. 使用场景与成功标准

集团员工在知识空间上传和阅读 PPT、PDF、Excel；编辑者负责更新、下载和打印源文件。第一期只部署本地开发环境，不推送 GitHub、不部署生产。

成功标准：

- PDF 上传后可直接在线阅读，不再只显示下载链接。
- PPT/PPTX 上传后转换为 PDF，并进入与 PDF 相同的统一阅读器。
- Excel 上传后可在网页中切换工作表、滚动查看和搜索单元格。
- `view` 权限只能阅读；`edit`、`delete`、`admin` 权限可以下载和打印。
- 直接复制文件 URL 不能绕过服务端权限。
- 上传、转换、替换、下载和容量统计支持实际文件类型。
- 转换或预览失败时仍保留原文件，并给出中文说明和可恢复路径。

## 2. 技术选择

### 2.1 PDF 与 PPT 阅读

采用 Mozilla PDF.js 作为渲染内核，通过 `react-pdf` 集成到 Next.js 客户端组件。选择理由：

- PDF.js 是成熟、活跃的开源 PDF 渲染基础，Apache-2.0 许可。
- `react-pdf` 使用 MIT 许可，适合实现 Academy 自己的阅读界面。
- 不采用需要商业许可的 `react-pdf-viewer`。
- 不直接嵌入浏览器 iframe，避免浏览器差异并获得统一权限和交互控制。

新增依赖前必须记录实际版本、许可证、安装体积和构建体积变化。阅读器使用动态加载，PDF Worker 独立输出，避免增加其他页面的首屏负担。

### 2.2 Excel 阅读

复用项目现有 `xlsx` 依赖，在客户端解析工作簿并生成只读表格，不增加新的表格依赖。第一期不支持在线编辑、公式重新计算、宏和复杂图表还原。

### 2.3 AI 使用边界

第一期不依赖 AI 模型完成基础阅读。第二期才增加逐页文字提取、AI 摘要、搜索结果跳页和引用页码；模型不可用时仍必须能正常阅读文件。

## 3. 文件处理架构

统一文件处理流程：

```text
上传请求
  → 服务端身份与文件校验
  → 建立 Document 记录（processing）
  → 原文件写入私有存储
  ├─ PDF：直接标记 ready
  ├─ PPT/PPTX：LibreOffice 转 output.pdf → ready / failed
  ├─ Excel：保留原文件 → ready
  └─ DOCX：保持现有解析流程
  → 返回文件元数据和处理状态
```

Document 需要具备或可推导以下字段：原始文件名、扩展名、MIME、文件大小、处理状态、处理错误、预览文件路径和更新时间。优先使用兼容字段或独立元数据结构；若必须调整 Prisma Schema，实施前先备份数据库并提供迁移与回滚步骤。

处理状态限定为：

- `processing`：文件已接收，正在生成预览。
- `ready`：可以在线阅读。
- `failed`：预览生成失败，但原文件保留。

第一期允许 PPT 转换继续同步执行，但界面必须展示明确状态；若实际大文件测试显示请求超时，再独立设计后台队列，不在本期提前引入队列依赖。

## 4. 统一阅读器

新增 `components/internal/` 下的独立阅读器组件，文档详情页只负责取得文档信息和权限后选择阅读器。

### 4.1 PDF/PPT 阅读器

桌面布局：

- 左侧：可折叠的页面缩略图，突出当前页。
- 中间：单页为主的阅读区域，支持适应宽度与适应页面。
- 顶部工具栏：上一页、下一页、页码输入、总页数、缩放、旋转、搜索和全屏。
- 下载与打印按钮只在 `edit` 及以上权限出现。

移动布局：

- 默认隐藏缩略图侧栏，通过按钮打开抽屉。
- 工具栏保留上一页、下一页、页码和全屏。
- 所有触控按钮区域不小于 44px。

性能原则：

- 阅读器必须动态加载并关闭 SSR。
- 仅渲染当前页和相邻页；缩略图按需生成。
- 不一次性用高分辨率渲染全部页面。
- PDF 获取接口支持浏览器 Range 请求时优先使用分段读取。

### 4.2 Excel 阅读器

- 顶部显示 Sheet 标签，默认打开第一个非空 Sheet。
- 表格区域横向和纵向滚动，首行作为视觉表头固定。
- 支持当前 Sheet 内的文本搜索和匹配计数。
- 空 Sheet、超大 Sheet 和解析失败提供中文状态。
- 第一版最多渲染当前 Sheet 的前 1,000 行，并提示“当前显示前 1,000 行”，防止浏览器冻结。
- 下载按钮仍只对 `edit` 及以上权限显示。

## 5. 权限与文件访问

文件不再依赖 `/public/uploads/...` 作为最终阅读地址。新增受保护的文件输出 API：

- 预览：拥有 `view` 及以上权限可访问。
- 下载原文件：拥有 `edit` 及以上权限可访问。
- 打印：前端仅对 `edit` 及以上开放；打印所需文件请求仍经过服务端权限校验。

后端按文档 ID 查询实际文件元数据，不接受用户传入任意磁盘路径。响应设置正确的 Content-Type、Content-Disposition、缓存控制和范围请求头。所有读取和下载记录到审计日志。

## 6. 上传、替换与存储修复

- 服务端校验扩展名、MIME 和文件大小；前端 `accept` 仅作为交互提示。
- 允许类型保持 DOCX、PPT/PPTX、PDF、XLS/XLSX；TXT、ZIP 和旧 DOC/PPT 是否继续允许由现有产品范围保留，但不能假装具备在线预览。
- 文件写入失败不得静默忽略，数据库记录必须回滚或标记失败。
- 覆盖上传复用统一文件处理器，不再把 PPT 当 DOCX 保存和解析。
- 替换重要文档前保留 `DocumentHistory` 或等价快照，并记录审计。
- 容量统计遍历实际原文件，而不是只统计 `original.docx`。
- PPT/PPTX 临时输入使用真实扩展名，兼容旧 `.ppt` 格式。

## 7. 错误处理

- 上传失败：保留表单内容，显示中文原因。
- PPT 转换失败：文档状态为 `failed`，管理员可重新处理；仅有查看权限者看到“暂时无法预览”，不能下载原文件。
- PDF 加载失败：显示重试按钮，并提示联系文档管理员。
- Excel 解析失败：显示文件可能损坏或格式不受支持，不输出底层堆栈。
- 权限不足：API 返回 403，前端显示“你没有下载或打印权限”。
- 文件不存在：API 返回 404，并记录可定位日志。

## 8. 测试与本地验收

自动测试覆盖：

- 文件类型与 MIME 校验。
- `view` 可预览但不能下载。
- `edit` 可预览、下载和打印。
- PDF Range 请求和完整请求。
- PPT 转换成功、LibreOffice 缺失、超时和损坏文件。
- 替换上传按实际类型保存。
- Excel 多 Sheet、空 Sheet、超 1,000 行和损坏文件。
- 容量统计包含 DOCX、PPT、PDF 和 Excel。

本地人工验收：

- 使用至少一份 PPTX、一份旧 PPT、一份原生 PDF、一份多 Sheet Excel。
- 桌面端验证缩略图、翻页、页码、缩放、搜索、旋转和全屏。
- 手机宽度验证缩略图抽屉和 44px 触控区域。
- 分别用 viewer 与 editor 权限验证按钮和直链访问。
- 运行 TypeScript 检查、相关测试和生产构建。

## 9. 交付阶段

### 第一阶段

统一文件元数据、服务端校验、受保护预览/下载、替换上传和容量统计。

### 第二阶段

实现 PDF/PPT 统一阅读器与 Excel 只读阅读器，并完成权限界面。

### 第三阶段

本地开发服务器联调、样例文件验收、性能检查和文档更新。完成后保留本地分支，由用户决定是否合并或推送。

### 后续独立阶段

逐页文字提取、全文搜索跳页、AI 摘要页码引用、扫描件 OCR 和后台转换队列。
