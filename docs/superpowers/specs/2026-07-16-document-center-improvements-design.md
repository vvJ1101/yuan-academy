# Academy 文档中心改进设计

## 目标

将当前未提交的文档中心改动整理为一个边界明确、可测试、可独立回滚的功能：扩展常用办公文件上传，准确展示文件类型，修正文档目录筛选和首页推荐重复，同时保持现有权限模型与 AI 解析流程不被扩大修改。

## 范围

本阶段包含：

- 支持 DOC、DOCX、PPT、PPTX、PDF、XLS、XLSX、TXT、ZIP 文件上传。
- DOCX 继续进入 Markdown 解析流程，PPT/PPTX 继续使用现有转换流程，其余格式保存原文件并提供下载。
- 文档列表 API 返回实际保存文件的扩展名和文件大小。
- 文档列表优先根据实际扩展名展示图标与类型标签。
- 修正知识空间、公司与子文件夹筛选，使选中父级时包含全部后代目录。
- 将知识空间入口整合到内部导航，移除文档页重复的左侧目录栏。
- 首页“为你推荐”排除已经出现在最近浏览或热门列表中的文档，并限制为四条。

本阶段不包含：

- 不实施 `academy-security-permissions` 计划中的会话、解析接口和异步权限重构。
- 不提交 `dev-explorer-ide` 生成产物。
- 不修改订货政策功能。
- 不引入对象存储、病毒扫描服务或新的第三方依赖。

## 上传架构

上传接口在创建文档记录前完成基础输入校验：登录与权限沿用现有边界；文件扩展名必须位于允许列表；文件不得超过项目定义的上限；空文件和缺少文件名的请求被拒绝。服务端从原始文件名提取并规范化扩展名，不接受包含路径片段或允许列表以外的后缀。

保存和处理按类型分流：

- DOCX：保存 `original.docx`，再调用现有 `parseDocx`。
- PPT/PPTX：保存相应原文件，再调用现有 PPT 转换流程。
- PDF、XLS、XLSX、DOC、TXT、ZIP：保存 `original.<ext>`，写入说明型内容和下载链接，不进行内容解析。

数据库创建、磁盘写入或后续转换任一步骤失败时，接口返回明确错误，并尽力删除本次请求创建的数据库记录和文件目录，避免残留空文档。

## 数据与界面

文档列表响应增加可空的 `fileType` 和 `fileSize`。服务端在文档私有目录支持的文件名中查找实际原文件，返回第一个匹配项的扩展名和字节数。前端类型图标与标签优先使用 `fileType`，仅在旧数据没有该字段时回退到标题和分类推断。

上传弹窗接受批准的扩展名。上传成功后保持弹窗结果态，用户可选择完成或对支持的文档启动现有 AI 解析；默认不自动触发 AI。

内部侧边栏展示知识空间及其目录树。文档列表页不再维护第二套重复导航，只负责当前目录面包屑、工具栏、文件列表和上传弹窗。父目录、知识空间或公司筛选均递归包含后代文件夹。

## 推荐去重

推荐接口建立已经展示的文档 ID 集合。最近浏览和热门文档进入集合后，“为你推荐”过滤这些 ID，并最多返回四条。风险提醒保持独立，不参与这一轮去重，避免改变其告警覆盖率。

## 安全与错误处理

- 上传格式由服务端允许列表决定，前端 `accept` 仅用于用户体验，不能作为安全边界。
- 扩展名统一转为小写，并拒绝无扩展名、多余路径片段和不支持格式。
- 设置明确的单文件大小上限，并在读取或写入前拒绝超限请求。
- 响应不暴露服务器绝对路径或底层异常堆栈。
- 本阶段不宣称 ZIP 内容安全；ZIP 仅作为不解析的下载附件保存。生产部署仍应在后续接入恶意文件扫描。

## 测试与验收

自动化测试覆盖：

- 允许和拒绝的上传扩展名。
- 超限、空文件和异常写入。
- DOCX、PPT/PPTX 与直接保存格式的处理分支。
- `fileType`/`fileSize` 响应与旧数据回退。
- 父级目录递归筛选。
- 推荐列表去重和四条上限。

全局验证运行 Prisma schema 校验、项目测试、TypeScript 检查、生产构建和 `git diff --check`。人工冒烟检查上传结果态、文件图标、目录导航和下载链接。

## Git 与发布

实现使用 `agent/document-center-improvements` 分支。规格文档、实施计划和功能代码按清晰边界提交；仅推送该分支并创建草稿 PR 到 `main`。现有安全计划、开发文档、分析产物及不属于本功能的工作区改动保持未提交。

回滚时可关闭 PR；若已合并，则按功能提交逐项 revert。回滚上传接口时不自动删除此前已上传的业务文件，避免数据丢失。
