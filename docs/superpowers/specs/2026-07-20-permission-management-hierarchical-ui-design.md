# 权限管理层级化 UI 设计

> 日期：2026-07-20  
> 范围：`/internal/admin/role-permissions` 角色权限管理页  
> 目标：把现有“权限树难找、菜单/按钮/数据混在一起”的问题，改造成更符合业务理解的层级化权限配置体验。

## 1. 场景还原

### 谁在用

- 超级管理员
- 人事/系统管理员
- 负责给部门或角色分配权限的人

### 想干什么

- 快速找到某个业务模块的权限，例如“品牌资料 / 品牌对接信息 / 查看市场字段”。
- 给不同部门分配符合职责的权限，例如市场部只看市场字段，商品部维护完整品牌资料。
- 看懂当前角色到底拥有哪些页面、按钮和数据范围权限。

### 怎么算成功

- 管理员不用记权限 key，也能找到正确权限。
- 权限配置按“模块 → 页面 → 操作”呈现。
- 高危权限有明显提示，避免误勾。
- 保存前能看到“当前角色最终会获得什么能力”的摘要。

## 2. 当前问题

现有权限管理页已经使用树形数据，但体验仍然偏技术视角：

- 权限节点太多，菜单、页面、按钮混在一棵树里。
- 权限 key 直接展示，信息密度高，普通管理员难判断含义。
- 品牌资料、订货政策、品牌对接信息这类业务权限不够聚合。
- 缺少按部门职责的快捷模板。
- 数据权限和功能权限虽然在同一个弹窗，但心智上还没有形成“先选能做什么，再选能管哪些数据”的清晰流程。

## 3. 设计原则

1. **业务语言优先**  
   默认展示“查看品牌对接信息 / 市场字段”，而不是优先展示 `brandContact.viewMarketFields`。

2. **模块化查找**  
   先选择业务模块，再配置模块下的页面和按钮，减少一次看到的节点数量。

3. **权限分层明确**  
   页面权限、按钮权限、数据权限分区显示，但保存时仍提交同一套角色权限。

4. **高危权限防错**  
   删除、全部数据、完整字段、上传、用户管理等权限需要醒目标识。

5. **保留现有后端结构**  
   继续使用 `SysMenu / SysRoleMenu / SysRole.dataScope`，不新增复杂权限表，降低上线风险。

## 4. 推荐方案

采用“左侧模块导航 + 中间分组权限树 + 右侧已选摘要”的三栏布局。

```text
权限配置弹窗
├─ 左侧：模块
│  ├─ 知识中心
│  ├─ 品牌资料
│  ├─ 智能应用
│  └─ 系统管理
├─ 中间：当前模块权限
│  ├─ 页面权限
│  ├─ 操作权限
│  └─ 高危权限
└─ 右侧：当前角色摘要
   ├─ 已选页面
   ├─ 已选操作
   ├─ 数据范围
   └─ 风险提示
```

## 5. 信息架构

### 5.1 模块分组

| 模块 | 包含内容 |
|---|---|
| 知识中心 | 我的上传、文档上传、编辑、删除、下载、打印、SOP、收藏 |
| 品牌资料 | 品牌资料入口、订货政策、品牌对接信息 |
| 智能应用 | AI 助手、AI 搜索、AI 推荐、风险分析、FAQ、全局搜索 |
| 系统管理 | 管理中心、用户、组织、角色、文件夹、学习路径、统计、审计、设置 |

### 5.2 品牌资料模块示例

```text
品牌资料
├─ 页面权限
│  ├─ 品牌资料入口
│  ├─ 订货政策
│  └─ 品牌对接信息
├─ 订货政策操作
│  ├─ 查看订货政策
│  ├─ 编辑订货政策
│  ├─ 上传订货政策
│  ├─ 解析订货政策
│  ├─ 导出订货政策
│  ├─ 删除订货政策
│  └─ 删除全部订货政策（高危）
└─ 品牌对接信息操作
   ├─ 查看市场字段
   ├─ 查看完整字段（敏感）
   ├─ 编辑品牌对接信息
   ├─ 上传品牌对接信息
   ├─ 导出市场字段
   └─ 导出完整字段（敏感）
```

## 6. 交互设计

### 6.1 搜索

权限弹窗顶部增加搜索框：

- 输入“品牌”时，只显示品牌资料相关节点。
- 输入“市场字段”时，自动定位 `查看市场字段`。
- 搜索结果保留父级路径，例如：`品牌资料 / 品牌对接信息 / 查看市场字段`。

### 6.2 快捷模板

增加“应用推荐模板”区域：

| 模板 | 默认勾选 |
|---|---|
| 市场部模板 | `menu.brand`、`menu.brand.contact`、`brandContact.viewMarketFields`、`menu.brand.ordering`、`brandOrdering.view` |
| 商品部模板 | 品牌对接完整查看、编辑、上传、导出完整字段；订货政策查看 |
| 品牌部模板 | 订货政策查看、编辑、上传、解析、导出；品牌对接按需查看 |
| 只读模板 | 基础页面查看 + 收藏 + 搜索，不含编辑、上传、删除 |

模板不是角色锁死规则，只是批量勾选建议。最终仍以管理员保存的勾选结果为准。

### 6.3 已选摘要

右侧摘要用人话解释最终能力：

```text
市场部当前能力：
- 可进入品牌资料
- 可查看订货政策
- 可查看品牌对接信息中的市场字段
- 不可查看完整商品字段
- 不可编辑、上传、删除品牌资料
```

### 6.4 高危提示

以下权限显示红色或橙色标签：

- 删除类：`*.delete`、`*.deleteAll`
- 上传/替换类：`*.upload`、`document.replace`
- 完整敏感字段：`brandContact.viewFullFields`、`brandContact.exportFullFields`
- 全局管理：`settings.manage`、`audit.view`、`role.assignPermission`、`role.assignDataScope`
- 数据范围：`ALL`

保存时如果包含高危权限，弹窗显示二次确认摘要。

## 7. 数据来源

| 界面字段 | 数据来源 |
|---|---|
| 角色列表 | `SysRole` |
| 角色已选权限 | `SysRoleMenu` |
| 权限树 | `SysMenu` |
| 权限 key / 类型 / 父子层级 | `SysMenu.permission`、`SysMenu.type`、`SysMenu.parentId` |
| 数据权限 | `SysRole.dataScope`、`SysRole.customDeptIds` |
| 部门树 | `SysDept` |
| 用户分配 | `SysUserRole` + `User` |

## 8. 技术方案

### 8.1 前端组件

优先改造现有文件：

- `src/components/internal/permissions-management/index.tsx`

建议拆出小组件，避免单文件继续膨胀：

- `src/components/internal/permissions-management/module-sidebar.tsx`
- `src/components/internal/permissions-management/permission-tree-panel.tsx`
- `src/components/internal/permissions-management/selected-summary.tsx`
- `src/components/internal/permissions-management/permission-template-bar.tsx`
- `src/components/internal/permissions-management/permission-risk-tags.tsx`

### 8.2 后端 API

优先复用现有接口：

- `GET /api/admin/menus/tree`
- `GET /api/admin/roles/[id]/permissions`
- `PUT /api/admin/roles/[id]/permissions`
- `GET /api/admin/roles/[id]/dataScope`
- `PUT /api/admin/roles/[id]/dataScope`

第一阶段不新增 API。前端根据 `SysMenu` 树和权限 key 前缀完成分组展示。

### 8.3 权限模板

模板先写成前端常量，来源于当前权限矩阵：

- 市场部模板
- 商品部模板
- 品牌部模板
- 只读模板

后续如果模板需要后台可配置，再单独设计模板表。

## 9. 错误处理

- 权限树加载失败：显示“权限数据加载失败，请刷新重试”。
- 保存失败：保留用户已勾选状态，不关闭弹窗。
- 高危权限确认取消：不保存，返回编辑状态。
- 搜索无结果：显示“没有匹配的权限点”。

## 10. 测试验证

### 10.1 手工验证

1. 进入 `/internal/admin/role-permissions`。
2. 打开“市场部”角色配置。
3. 搜索“品牌对接”。
4. 确认能快速定位：
   - 品牌资料入口
   - 品牌对接信息
   - 查看市场字段
5. 应用“市场部模板”，确认不勾选完整字段、编辑、上传、删除。
6. 保存后，用市场部账号登录验证页面和字段可见性。

### 10.2 自动化验证

- 权限分组函数测试：输入 `SysMenu` 树，输出正确模块。
- 权限摘要函数测试：市场部权限输出正确中文摘要。
- 高危权限识别测试：删除、完整导出、全部数据能被识别。

## 11. 回滚方案

- 前端改造只影响权限管理 UI，不改变后端权限判断。
- 如上线后 UI 不好用，可回滚权限管理页组件到上一版。
- 后端 `SysMenu / SysRoleMenu` 数据不需要回滚，因为本方案不改表结构。

## 12. 非目标

本次不做：

- 新增权限模板数据库表。
- 修改 `SysMenu / SysRoleMenu / SysRole` 表结构。
- 改动文档解析、AI prompt、FTS 索引等禁区文件。
- 改动品牌对接信息的数据字段规则。
